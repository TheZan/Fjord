## Phase 6 — Performance foundation

Goal: Fjord has a measurable performance architecture — published SLOs, realistic torture fixtures, end-to-end latency attribution, long-lived repository state, generation-scoped invalidation, snapshot-first switching, and bounded transport — rather than a subjective impression of speed. Spec: [`specs/performance.md`](specs/performance.md).

Ordered by dependency: measurement before fixtures, fixtures before budgets, budgets before architecture changes, architecture before gates.

- [x] **P6-01** — Ratify the SLO catalogue and measurement methodology (spec §1). Sixteen SLOs, each with a scenario identifier (the name `fjord-bench` emits, so budget/measurement/CI result can be joined), the fixture it runs against, and either a measured anchor or an explicit *provisional* marker — ten of sixteen were initially provisional. Measurement rules are stated per class, including P95 over ≥20 repetitions, the report-then-gate rule, and the refusal to compare across platforms. The existing checkpoints in [`benchmarks/p4-18-release.md`](benchmarks/p4-18-release.md) are absorbed as anchors rather than contradicted; P6-18 later audited every marker.
- [x] **P6-02** — `fjord-bench`: fixture manifests and reuse. Each generated fixture writes `.fjord-bench-manifest.json` with its parameters and schema version, written last so an interrupted generation regenerates; reuse requires an exact parameter match, changed parameters regenerate, `--force` regenerates unconditionally, and a non-empty directory that is not ours is refused under either flag setting (spec §2). Replaces the old "does `.git` exist" check, which reused a 200-commit fixture for a 50 000-commit run while reporting the requested parameters. Every run prints the fixture hash. Ten unit tests cover match, mismatch, force, legacy marker-only fixtures, the refusal path, and canonical-JSON stability; verified end to end that a changed `--commits` produces the requested history.
- [x] **P6-03** — Machine-readable benchmark output: `--scenario NAME --json PATH|-` emits a versioned document with the scenario, fixture kind/hash/generated flag, environment (OS, architecture, CPU model, profile), every metric with its unit, and every budget with both sides of the comparison; the existing `key=value` stdout is unchanged (spec §10). The record is written before a failing budget fails the run, so a regression is visible in the result and not only in the exit code. Seven unit tests cover the document shape, units, budget records, non-finite values, and file emission; verified end to end that an over-budget run still writes its record and exits non-zero, and that a within-budget run exits zero.
