## What the numbers say

**The first history page costs the whole history.** 3639 ms for 30 commits on a
packed 500k-commit repository with a commit-graph, against Git's own 33 ms for
the identical request. This is the finding the deep fixture existed to produce,
and it is architectural rather than a constant factor: libgit2's topological sort
has no commit-graph acceleration, so it buffers the reachable history before
yielding anything. `P6-21` owns it.

**Refs are fine.** 232 ms for 10 001 branches and 5 000 tags, inside SLO-16. An
earlier reading of 2005 ms sent a task off to optimize the refs path; that number
was an unpacked-fixture artifact and the task was rewritten.

**SLO-10 is unreachable with the current transport.** `file_diff` alone spends
611 ms against a 600 ms budget, before serializing 2 694 458 `DiffLine` values
across IPC and before painting a row. The windowed transport (`P6-16`) is a
prerequisite for this SLO, not an optimization of it.

**Noise costs more than size.** `wt-noisy` holds 50 000 tracked files and takes
798 ms; `wt-huge` holds three times as many tracked files and no noise, and takes
568 ms. 220 000 ignored and untracked files are more expensive than 100 000
additional tracked ones.

## Caveat: `live_refresh` is sequential

`measure_workspace_dashboard` refreshes the 100 repositories in a plain loop,
while the application fans out through a bounded worker pool. 5132 ms is
therefore the total work, not the latency a user would see, and it must not be
read as a workspace-refresh budget. Recorded because the total is still useful —
labelled because it does not measure the product's path.

## Two fixture defects found and fixed

Both were defects in how the fixtures were built, and both would have produced
confident, wrong conclusions.

**Untracked and ignored files were parked in their own subtrees.** Git skips a
wholly-ignored directory outright and collapses a wholly-untracked one into a
single `?? scratch/` entry without descending, so `wt-noisy`'s 220 000 noisy
files cost about as much as one and Fjord reported `dirty_count = 1`. The fixture
measured 145.7 ms — *faster* than `wt-huge`, on more files. The layout is now
interleaved through the tracked directories, `dirty_count` reads 20 000, and the
measurement is 798 ms.

**Nothing was ever packed.** The generator writes objects one commit at a time,
leaving `hist-deep` with roughly 2.5 million loose object files and no packfile.
No repository in the wild looks like that. On NTFS every object read became its
own file open: the first-page read sat at 5% CPU for over twelve minutes without
finishing. Packed, the same read takes 3639 ms. Packing now runs on every
materialize, repairing existing fixtures in place rather than discarding hours of
generation.

The shared lesson: a fixture is only validated by the reader under test. The
`wt-noisy` layout was asserted through `git2` in a passing test while `gix` — the
engine Fjord actually reads with — saw something entirely different.

## Reproducing

```bash
node scripts/generate-fixtures.mjs --list
```

Generate from a **normal, non-elevated shell**. Fixtures created by an elevated
process are owned by the Administrators group, and libgit2 then refuses to open
them from an ordinary session — which is how `P5-27` was found.
