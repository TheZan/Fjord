## What the numbers say

**SLO-16 is wrong, or the refs path is.** Two seconds to enumerate 10 001
branches and 5 000 tags from a *packed* refs file is not a budget problem that
tuning a threshold fixes. It is slow enough to dominate opening any repository
with a lot of refs, which is every long-lived repository at a company that does
not prune. `P6-21` profiles before anyone adjusts a number.

**SLO-10 is unreachable with the current transport.** The backend's `file_diff`
alone spends 601 ms against a 600 ms budget — before serializing 2 694 458
`DiffLine` values across IPC, before the frontend deserializes them, and before a
single row is painted. The windowed transport in `specs/performance.md` §9
(`P6-16`) is a prerequisite for this SLO, not an optimization of it.

**SLO-6 looks reachable.** 299 ms at 150k tracked files, against 800 ms at 300k.
If the cost stays roughly linear the 300k variant lands near 600 ms, which is
inside the budget but not comfortably. The 300k run is still needed.

## `wt-noisy` is not recorded here

The first `wt-noisy` run measured 145.7 ms — *faster* than `wt-huge`, despite
holding 270 000 files against 150 000. That result was an artifact of the
fixture, not a property of Fjord.

The original layout parked ignored files under `generated/` and untracked files
under `scratch/`. Git skips a wholly-ignored directory outright and collapses a
wholly-untracked one into a single `?? scratch/` entry without descending into
it, which is why Fjord reported `dirty_count = 1` for twenty thousand untracked
files. The fixture's 220 000 noisy files cost about as much as one.

The layout is now interleaved: noise is spread through the same directories as
the tracked files, so nothing can be skipped or collapsed. The fixture's identity
changed with it, so the old directory regenerates rather than being reused. A
corrected measurement belongs in the next checkpoint.

The lesson is worth keeping: the fixture's own test asserted the right file
counts through `git2` and passed, while the engine Fjord actually reads with
(`gix`) saw something entirely different. A fixture is only validated by the
reader under test.

## Reproducing

```bash
node scripts/generate-fixtures.mjs --list
```

```bash
node scripts/generate-fixtures.mjs --only refs-many,diff-giant
```

Generate from a **normal, non-elevated shell**. Fixtures created by an elevated
process are owned by the Administrators group, and libgit2 then refuses to open
them from an ordinary session — which is also how `P5-27` was found.
