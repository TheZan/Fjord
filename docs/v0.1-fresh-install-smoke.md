# Fjord v0.1 fresh-install smoke

This checklist is the evidence contract for `P9R-09`. Automated coverage runs on
Windows, macOS, and Linux in the ordinary `backend-test` CI matrix:

```text
cargo test -p fjord-app fresh_install_smoke_restores_each_repository_once_after_restart
```

The test uses a new application-data directory and isolated local Git fixtures.
It creates a workspace, opens an existing repository, clones a fixture bare
remote, creates and commits a local repository, adds `origin`, pushes and sets
upstream, fetches and fast-forwards a peer update, restarts the real service
composition against the same database, and asserts that all three repositories
and the workspace are restored exactly once.

Native pickers, installers, desktop launch, OS credential UI, and persistence
through an installed packaged binary require the following manual pass. Do not
reuse a developer profile: start with the platform's Fjord application-data
directory absent, and use disposable local repositories with no credentials.

| Platform | Package | Prerequisites | Expected result | Evidence location |
|---|---|---|---|---|
| Windows 11 x64 | Signed NSIS installer (`Fjord_0.1.0_x64-setup.exe`) | Clean Windows VM; system Git on `PATH`; installer artifact from the candidate Release run | Install and launch without a terminal; create workspace; Open/Scan cancellation returns to choices; open, clone, and create fixtures; commit; add `origin`; **Push & Set Upstream**; peer fetch/pull; quit and relaunch; one entry per repository and preserved workspace | Release run URL plus `fresh-install/windows-11.md`; attach installer SHA-256 and screenshots before gate review |
| macOS 13+ (Apple Silicon) | Signed/notarized `.app` or DMG | Clean macOS VM/device; system Git; notarized candidate artifact | Gatekeeper accepts the app; the complete lifecycle above passes; app relaunch restores each repository once; native folder pickers and cancellation behave correctly | Release run URL plus `fresh-install/macos-arm64.md`; attach artifact SHA-256, notarization result, and screenshots |
| Ubuntu 22.04+ x64 | AppImage | Clean Ubuntu VM with required WebKit/FUSE runtime and system Git; candidate AppImage | AppImage launches without developer tooling; the complete lifecycle above passes; relaunch restores each repository once; desktop integration does not require repository credentials | Release run URL plus `fresh-install/ubuntu-22.04.md`; attach artifact SHA-256, launch log, and screenshots |

Each evidence note records: date, tester, exact OS build, package filename and
SHA-256, Git version, CI/Release run URL, every step as pass/fail, screenshots or
bounded sanitized logs, and every issue link. Credentials, repository contents,
and URLs with userinfo must never be attached.
