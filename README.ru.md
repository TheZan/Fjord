### Обзор рабочего пространства

![Обзор рабочего пространства Fjord с карточками статуса репозиториев](assets/screenshots/workspace-overview.png)

Репозитории сгруппированы в рабочие пространства. На каждой карточке видны
текущая ветка, ahead/behind, число незакоммиченных файлов и конфликты — так
состояние всех проектов, с которыми вы работаете, помещается на один экран.
**Fetch all** и **Pull all** выполняются по всему пространству параллельно.

### История репозитория

![Граф коммитов с топологией веток и слияний, дерево веток и инспектор коммита](assets/screenshots/repository-history.png)

Внутри репозитория — граф коммитов с настоящей топологией веток и слияний,
слева локальные и удалённые ветки, теги и remotes, справа инспектор со списком
файлов выбранного коммита.

### Индексация и diff'ы

![Незакоммиченные изменения с постановкой по hunk рядом с подсвеченным diff](assets/screenshots/staging.png)

Незакоммиченные изменения разделены на staged и unstaged и показываются списком
или деревом. В индекс можно добавлять и убирать целые файлы, отдельные hunks или
выбранные строки, там же — отмена изменений, commit, amend и commit & push.

### Темы и языки

![Тот же diff в тёмной теме](assets/screenshots/diff-dark.png)

Светлая, тёмная или системная тема, а также русский, английский, немецкий,
французский и испанский — всё переключается на лету в **Настройках**.

## Что вы получаете

- **Рабочие пространства вместо одного репозитория за раз.** Группируйте
  репозитории так, как вы думаете о проектах, а не так, как они лежат на диске.
- **Один дашборд на всё, чем вы заняты.** Ветка, ahead/behind, изменённые файлы
  и конфликты по каждому репозиторию, которые обновляет фоновый watcher
  файловой системы, а не периодический опрос.
- **Массовые операции.** Fetch, pull или открытие всего пространства в IDE одним
  действием — параллельно, на ограниченном пуле воркеров.
- **Настоящий граф коммитов.** Топология веток и слияний, а не плоский список,
  плюс инспектор коммита с его файлами.
- **Индексация по строкам.** Целые файлы, отдельные hunks или выбранные строки —
  в индекс, из индекса или в отмену; diff в unified и split режимах.
- **Ваши Git-креденшелы остаются вашими.** Сетевые операции идут через системный
  Git, поэтому credential helpers, SSH-агент, proxy и корпоративные сертификаты
  продолжают работать. Fjord не хранит пароли, токены и ключи.
- **Отмена для опасных действий.** Перед разрушающей операцией показываются её
  точные последствия, а Recovery Center на основе reflog возвращает работу.
- **Всё с клавиатуры.** Командная палитра (`⌘K` / `Ctrl+K`), переключатель
  репозиториев и глобальный поиск по репозиториям, веткам и коммитам.
- **Тихо и нативно.** Ядро на Rust за нативным webview: небольшой размер
  установки и низкая цена простоя, без встроенного браузера.

## Быстродействие

Чтения ограничены по объёму: история и diff'ы постраничные, статус и история
кэшируются, переключение репозитория восстанавливается из сохранённого снапшота
до начала живой работы с Git, а подсветка синтаксиса выполняется в воркере, вне
render path.

Измерено на синтетических фикстурах в release-сборке:

| Сценарий | Результат |
|---|---|
| Открытие репозитория (50k коммитов) | 0,5 мс |
| Статус (50k коммитов, 200 файлов) | 3,5 мс |
| Страница истории, 200 коммитов из 50k | 9,7 мс |
| Живое обновление статуса, 24 репозитория | 62 мс |
| Чтение дашборда из кэша, 24 репозитория | 0,1 мс |
| Глобальный поиск по 24 репозиториям | 57 мс |
| Первое окно diff на огромном packed-diff (P95) | 34,6 мс |

Полные прогоны, фикстуры и отчётность по регрессиям — в
[`docs/benchmarks/`](docs/benchmarks/).

## Установка

Fjord работает на **Windows 11 x64**, **macOS 13+** (Intel и Apple Silicon) и
**Ubuntu 22.04+ x64**. Подписанный установщик Windows, notarized-пакет macOS и
Linux AppImage — на [странице релизов](https://github.com/TheZan/Fjord/releases).

## Сборка из исходников

Нужны Node.js 22+, stable Rust, системный Git и
[зависимости Tauri](https://v2.tauri.app/start/prerequisites/):

```bash
npm ci
npm run tauri dev
```

## Git и авторизация

Fetch, сетевой этап pull, push и операции с удалёнными ветками выполняет
установленный системный Git, поэтому продолжают работать ваши credential
helpers (например, Git Credential Manager), SSH agent и config, proxy и
сертификаты. Fjord не хранит пароли, токены и приватные ключи. Если Git или SSH
всё-таки нужен ввод, встроенный одноразовый askpass показывает нативное окно
только для этой операции.

В **Настройки → Git** видны путь и версия Git и окружение credentials, там же
можно выбрать другой executable и выполнить read-only проверку подключения.

Если сетевая операция не удалась:

- **Git не найден** — установите Git или выберите executable в Настройки → Git.
- **Ошибка авторизации** — настройте рекомендованный хостингом credential helper
  и повторите проверку подключения. PAT в настройках Fjord не принимает.
- **SSH-ключ не найден** — проверьте `ssh-add -l`, `SSH_AUTH_SOCK` и `~/.ssh/config`.
- **Ошибка host key** — подключитесь через `ssh` в терминале и сверьте
  fingerprint. Fjord не отключает проверку host key.
- **Ошибка сертификата или proxy** — исправьте системные настройки Git
  `http.ssl*` / `http.proxy`. Глобальный Git config Fjord не меняет.
- **Подробности** — раскройте **Raw diagnostics** после неудачной проверки. Логи
  лежат в каталоге app-data платформы, в папке `logs`, credentials в них
  вырезаются.

## Участие в разработке

Небольшие и сфокусированные вклады и issue reports приветствуются. Настройка
окружения и обязательные проверки описаны в [`CONTRIBUTING.md`](CONTRIBUTING.md);
архитектура и контракты подсистем — в [`docs/SDD.md`](docs/SDD.md) и
[`docs/specs/`](docs/specs/). Об ошибках сообщайте через шаблоны GitHub Issues,
об уязвимостях — приватно, как описано в [`SECURITY.md`](SECURITY.md); не
прикладывайте к публичным issue credentials и содержимое приватных репозиториев.
